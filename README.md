# hh-autopilot

Поиск работы на hh.ru через своего агента: собрать вакансии, отсеять мусор, написать письма под каждую, отправить отклики, разобрать ответы и посчитать воронку.

Одна установка, один конфиг, дальше работает по команде. Все данные лежат локально, наружу ничего не уходит.

---

## Зачем это

Ручной поиск работы на hh устроен одинаково у всех: десятки однотипных вакансий, половина с холодными звонками, зарплата в объявлении указана до вычета, а письмо писать некогда, поэтому уходит пустой отклик. Через две недели непонятно, куда ты откликался и кто пропал.

hh-autopilot закрывает эту рутину:

- собирает вакансии по нескольким трекам (у вас может быть 2 или 3 резюме под разные роли);
- отсеивает холодный поиск, ГПХ и вакансии ниже вашей планки по деньгам на руки;
- пишет письмо из ваших же фактов, а не из пересказа вакансии;
- отправляет отклики с защитой от дублей и дневным лимитом;
- показывает, кто ждет ответа, и считает воронку.

## Что умеет и чего не умеет

Умеет:

- искать по API hh с фильтрами по региону, удаленке и зарплате;
- читать полный текст вакансии, включая брендированные описания (в обычном описании их нет);
- считать деньги на руки, а не до вычета;
- собирать письма из блоков профиля по темам вакансии;
- проверять письмо перед отправкой: плейсхолдеры, длина, стиль;
- вести журнал отправленного и не откликаться дважды;
- отвечать в чаты по заготовленному словарю;
- строить отчет в xlsx или csv.

Не умеет и не будет:

- обходить капчу. Капча это сигнал остановиться, а не задача для обхода;
- работать без вашего аккаунта hh и вашей авторизации;
- придумывать опыт, которого нет. Блоки письма берутся только из вашего профиля;
- гарантировать, что автоматические отклики не нарушают правила hh. Это ваша ответственность, см. раздел про безопасность.

## Быстрый старт

Нужен Python 3.12 или новее. Это требование самой библиотеки hh-applicant-tool, начиная с версии 2.5 она собирается только под 3.12 и выше.

```bash
git clone https://github.com/masterofnuggets313/hh-autopilot.git
cd hh-autopilot
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux и macOS
source .venv/bin/activate

pip install -e ".[xlsx]"
```

То же самое одной командой, если не хочется по шагам: `bash scripts/setup.sh` на Linux и macOS, `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1` на Windows. Скрипт проверит версию Python, создаст окружение, поставит пакет и разложит примеры конфигов.

Дальше пять шагов.

**1. Авторизация на hh.** Пакет `hh-applicant-tool` проводит OAuth и хранит токен локально.

```bash
hh-applicant-tool auth
```

Токен ляжет в каталог по умолчанию, hhjob его найдет. Если хотите держать токен в отдельной папке, впишите путь в `HH_CONFIG_DIR` в `.env`: hhjob передаст его библиотеке при каждом вызове. Для самой команды `hh-applicant-tool auth` это другая переменная, `CONFIG_DIR`, поэтому при отдельной папке авторизуйтесь так: `CONFIG_DIR=/путь hh-applicant-tool auth`.

**2. Конфиг.** Скопируйте примеры и заполните своими данными.

```bash
cp config.example.toml config.toml
cp profile.example.toml profile.toml
cp .env.example .env
```

В `config.toml` впишите id своих резюме и поисковые запросы. В `profile.toml` перепишите блоки своими фактами: цифры, команда, проекты. Пока в блоке остается слово `ЗАМЕНИТЕ`, отклик не отправится.

**3. Проверка.**

```bash
hhjob doctor
```

Покажет, авторизованы ли вы, какие резюме видны работодателям, сколько треков настроено и есть ли блоки для писем.

**4. Сбор вакансий.**

```bash
hhjob search --salary 100000
hhjob describe --limit 12
hhjob letters
```

`search` соберет и отфильтрует, `describe` скачает полные тексты, `letters` соберет письма и покажет проблемы, если они есть.

**5. Отправка.** Сначала вхолостую, потом по-настоящему.

```bash
hhjob apply --dry
hhjob apply --limit 8
```

Дальше по кругу: `hhjob chats` покажет, кто ждет ответа, `hhjob report` посчитает воронку.

## Как это работает

```
config.toml ──> search ──> filters ──> candidates.json
                                            │
                                   describe (полный текст)
                                            │
profile.toml ──> letters ──> проверка ──> letters.json
                                            │
                              apply + журнал ──> отклики на hh
                                            │
                                  chats, report
```

Ключевые решения, которые стоит знать:

**Деньги считаются на руки.** hh не различает «до вычета» и «на руки», поэтому фильтр по зарплате пропускает вакансии ниже планки. Здесь все суммы приводятся к одному виду: 100 000 до вычета это 87 000 на руки.

**Брендированные описания читаются отдельно.** У части вакансий полный текст лежит в `branded_description` с HTML и CSS, а в обычном описании его нет. Без этого теряется блок условий и половина требований.

**Письмо собирается, а не генерируется.** Модель хорошо пишет текст и плохо знает вашу биографию. Поэтому письмо собирается из ваших блоков: приветствие, почему эта компания, два или три факта с цифрами, честный пробел, вопрос. Блоки подбираются по темам, найденным в тексте вакансии. Модель может пригодиться на этапе правки, но не на этапе фактов.

**Журнал отправленного обязателен.** Отклик нельзя отозвать. Поэтому перед каждым запросом идет проверка журнала, архива вакансии и текста письма.

## Команды

| Команда | Что делает |
|---|---|
| `hhjob doctor` | проверка установки, авторизации, резюме, конфига |
| `hhjob search --track sales --salary 100000` | собрать и отфильтровать вакансии |
| `hhjob describe --limit 12` | скачать полные описания |
| `hhjob letters` | собрать письма и проверить их |
| `hhjob apply --dry` | показать, что уйдет, ничего не отправляя |
| `hhjob apply --limit 8` | отправить отклики |
| `hhjob chats` | кто ждет ответа |
| `hhjob chats --reply replies.json` | ответить по словарю `{chat_id: текст}` |
| `hhjob report --out report.xlsx` | отчет по воронке |
| `hhjob lint письмо.md` | проверить текст на тире, ё, многоточия, числа словами |

## Второй канал: браузер

API hh покрывает отклик, переписку и отчеты, но не покрывает анкеты, тесты и формы, которые работодатель открывает в браузере. Для этого есть отдельный проект [marty-bridge](https://github.com/masterofnuggets313/marty-bridge): расширение Chrome плюс команды `mb`, которые открывают страницу, читают ее, кликают и заполняют поля.

Ставится отдельно и не обязателен. Если он есть, агент может пройти анкету на стороне работодателя, снять скриншот отправленной формы и проверить, что письмо ушло.

```bash
mb open https://hh.ru/vacancy/139327800
mb probe
mb do '[{"op":"click","text":"Откликнуться"},{"op":"probe"}]'
```

Держите их раздельно: hh-autopilot отвечает за данные и решения, marty-bridge за действия в браузере.

## Работа через агента

Репозиторий рассчитан на то, что им управляет агент (Claude, Codex, Cursor, любой другой с доступом к терминалу). Для этого в корне лежат:

- `AGENTS.md` — правила: что можно делать без спроса, что только с подтверждением, как проверять результат;
- `prompts/agent-workflow.md` — пошаговый сценарий «собрать, отобрать, написать, отправить, разобрать»;
- `prompts/style-ru.md` — требования к текстам писем;
- `prompts/vacancy-god-mode.md` — сценарий «найти вакансию мечты под жесткие условия».

Агенту достаточно сказать: «поработай по prompts/agent-workflow.md, отчет в конце». Дальше он читает `AGENTS.md` и действует по правилам.

## Безопасность и границы

- **Капча.** При частых откликах hh включает капчу на каждый запрос. Это защита, а не препятствие. Скрипт останавливается и просит снизить темп. Обхода капчи здесь нет и не появится.
- **Темп.** По умолчанию 10 откликов за запуск и 40 в сутки. Практика показывает, что после 60 или 70 откликов за день капча приходит на каждый.
- **Правила hh.** Автоматические действия могут нарушать пользовательское соглашение. Перед массовым использованием прочитайте правила площадки. Ответственность за аккаунт несет владелец аккаунта.
- **Личные данные.** `.env`, `config.toml`, `profile.toml`, `data/` и `.state/` в репозиторий не попадают: они в `.gitignore`. Перед публикацией форка проверьте, что не закоммитили свои id резюме и переписку.
- **Токены.** Токен hh лежит в каталоге `hh-applicant-tool`, а не в этом репозитории. Никому его не передавайте.

Подробнее в [SECURITY.md](SECURITY.md).

## Структура

```
hhjob/
  cli.py        команды
  config.py     .env, config.toml, profile.toml
  hh.py         обертка над hh-applicant-tool
  filters.py    холодный поиск, ГПХ, деньги на руки, оценка
  letters.py    сборка писем и проверки
  apply.py      отправка с защитой от дублей
  state.py      журнал отправленного
  report.py     воронка, xlsx и csv
  style.py      проверка текста
templates/letters/   шаблон письма
prompts/             сценарии для агента
tests/               тесты фильтров и писем
```

## Ограничения

Честно о минусах:

- верстка и API hh меняются, поэтому парсер описаний иногда придется править;
- оценка вакансий это регулярные выражения, а не смысл: она ошибается на нестандартных формулировках;
- письма получаются сухими, если в профиле мало цифр. Качество письма равно качеству ваших фактов;
- отчет считает переговоры, а не деньги: суммы офферов проект не знает;
- поддержки нескольких аккаунтов нет.
